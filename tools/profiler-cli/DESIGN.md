# UMM Profiler 设计方案

2026-11-18 · 设计稿

Profiler 为 310P 与 910B 之间的动态切分提供一份**带成本标注的计算图**。图保留算子、张量和依赖，把实测时间关联到对应的节点或节点组。heuristic 根据依赖、设备能力与成本从图中寻找区域，并检查切分边界。区域是搜索得到的一组节点，无需提前命名或登记。

可以把它理解为给 AST 加属性。执行图用 DAG 表达，因为一个张量可能被多处消费。块、层和阶段可以作为索引或显示标签。切点根据依赖、状态读写和后端能力检查。

当前以 310P 为主体。**310P 和 910B 各自预加载并驻留推理所需的只读权重。** 权重加载属于会话准备，测量与调度都从两端权重就绪后开始。切换区域只搬运跨设备的输入、输出和必要的状态，权重只计入各设备的常驻显存。

KV 等跨调用的持久状态保存在 310P，910B 可以在一次区域调用中使用临时副本，调用完成后将必要的更新写回 310P。受这一约束的扩散状态，其逐步交接也计入多步耗时。

## 输入与覆盖范围

用户入口保留三个输入。

| 输入 | 内容 |
| --- | --- |
| 模型 | U1.5 模型包及其权重身份 |
| 设备列表 | 本地 310P，以及通过 RPC 使用的远端 910B |
| 代表性负载 | 固定的理解和生图案例，包含输入及可复现的推理参数 |

对代表性负载中观察到的图采集全量结构。耗时覆盖尽量扩展到全图能可靠归因的执行单元。同一算子能单独计时，就把样本关联到该节点。多个算子融合执行，或只能共享一段可靠的计时，就保留整组的节点 ID 和耗时。只测到整图时就保留整图样本。未经测量的组内拆分保持未知。

理解输入记录本次实际处理量 `N` 和此前已有的上下文长度 `L`。长多图请求可能分成若干次图执行，使用每次执行的实际 shape 和上下文。比较 FFN 时主要覆盖 `N`，比较 Attention 时补足不同 `L`，尤其是同为单 token、历史长度不同的样本。生图先覆盖正式的 1024×1024、8 步配置，记录实际张量 shape、调用顺序和步间状态依赖。同一张图反复执行可以复用结构描述，每次调用仍保留自己的执行位置和状态读写关系。首轮按真实案例选取有代表性的点，固定权重、数值配置和链路，再分别记录首执行和热态样本。

## 执行流程

1. **跑基线。** 权重就绪后，在两台设备上分别用正常推理入口执行同一份负载。预热后记录请求耗时，分开测量会话内首次执行的准备开销。用请求结果核对后续测量的正确性。
2. **采结构。** 在结构轮导出实际计算图、放置、shape 和状态读写边界。对相同图结构复用描述。结构导出耗时用于检查采集开销。
3. **从粗到细分轮计时。** 先单独测请求和整图，再用独立轮次补节点组和算子时间。每轮只开启该粒度所需的观察，沿用后端已有的执行边界与设备时间线。细粒度采集优先补切点附近和粗粒度样本覆盖不到的位置。
4. **校准搬运与内存。** 用实际的 310P↔910B 路径测代表性边界张量、KV 读入与写回，并记录可观测的额外峰值显存。传输探针与真实混合执行分别计时。
5. **复测算法找到的方案。** 复测可执行的混合放置计划，核对实际放置、搬运、状态回写和输出，再与同条件的纯 310P、纯 910B 做请求耗时对照。

## 如何计算和测量

### 执行时间

同一段计算在两端用相同输入和等价状态实测。以权重已就绪时的执行时间为基准，另测图和缓冲的首次准备时间。设备内部的读写已经包含在执行耗时里。310P 使用可用的正常完成边界，910B 复用 RPC 服务端批量计时记录整图完成。各样本注明口径，包括是否含传输或等待。

**估算时优先使用能完整覆盖目标范围的最粗粒度实测。** 样本需要匹配输入形态、设备放置和计时口径。整图能覆盖时用整图时间，完整节点组能覆盖时用组时间。切点穿过一个计时范围时，只有受影响的部分需要下钻。选中父级样本后，其子级样本只用于分析。若某段没有适用的样本，将该段记为缺测。

例如，算法把连续三个 block 放到 910B，且已有相同放置和输入条件下的整段计时，就直接使用整段时间。如果切点落在中间 block 内，其余两个完整 block 仍可用各自的实测时间，只在中间 block 使用更细的样本。整段实测若包含了搬运，对应传输耗时也只计一次。

串行且互不重叠的细粒度样本可以相加得到估计。如果有并行或传输重叠，要按依赖和设备执行顺序估计完成时间。两端的融合或计时粒度可能不同，比较时要对齐到相同的逻辑计算范围。重要组合的耗时用真实混合执行复测。

两端的时间统一关联到同一逻辑图的节点或节点组。关联时用依赖、张量形态和算子参数核对等价范围。只有节点名称或执行顺序相同的样本保持待确认。

### 边界张量与持久状态

| 项目 | 从结构和当前状态计算 | 在两设备上测量 |
| --- | --- | --- |
| 激活及其他输入输出 | 由生产者、消费者和放置决定跨设备边。记录方向、shape、dtype、逻辑大小以及可确认的共享存储范围 | 实际搬运字节与完成时间，包括执行路径上的打包、主机中转和同步 |
| KV | 按远端 Attention 所在层区分历史读取和新增或修改范围。纯 FFN 的 KV 传输为零 | 测实际读入与写回路径。实现只有整块复制时，按实际复制量和耗时记录 |

给定一份放置方案，把生产者和消费者分别映射到设备，只为跨设备的依赖计搬运。同一份数据能被目标设备上的多个消费者复用时，按可复用的存储范围去重。实际复制路径和复用情况通过混合执行验证。

例如，一个 FFN 的输入和输出都是 4096×20 的连续 F32 张量，每份大小为 320 KiB。若前后区域均在 310P，单独迁移这个 FFN 需要上传 320 KiB、下载 320 KiB。若后续消费者也在 910B 且能直接使用这份输出，下载可以消除。这些是根据放置算出的逻辑字节，耗时还要用对应路径的传输样本估计。

首次 prefill 结束后，远端执行的层要把本次生成的全部 KV 写回 310P。已有前缀的 prefill 或 decode，需要上传远端 Attention 使用的历史 KV，原则上只写回新增或修改部分。下一次远端调用按 310P 所持状态重新计算输入量。

传输校准先覆盖两方向、代表性大小和消息组织方式。沿用正式复制路径，从发起复制测到数据可供消费者使用。若 RPC 等待同时包含远端计算，记为组合耗时。带宽拟合、插值和未测场景的预测由估计器完成。

### 内存占用

从图中可以计算逻辑上的同时存活量。对候选区域看张量何时产生、最后使用以及是否需要跨调用保留，按可确认的共享存储范围去重。计算出的活跃字节用于解释峰值和初筛。

两端权重就绪后的占用作为显存基线。计入当前已驻留的 KV 等状态后，测量区域执行期间新增的峰值，包括临时激活、工作区及新分配的缓冲。调度时将新增峰值与目标设备的可用显存比较，同一份常驻内存只计一次。使用低频设备采样时标明采样口径，缺测留空。

## 输出与估计方式

每份结果只记录一次适用配置，包括模型版本、设备、链路和数值设置。同一组传输样本使用同一复制路径和消息组织方式，变化时另分组。算法读取下表四类数据。

| 输出 | 字段 |
| --- | --- |
| 计算图 | 图和节点 ID、已知设备支持、张量大小、生产者与消费者、共享存储关系及可确认的状态读写。跨步依赖关联实际调用 |
| 执行耗时 | 所覆盖的图节点 ID、输入形态、设备、稳态耗时、首次额外准备耗时、计时口径 |
| 传输耗时 | 方向、实际搬运字节、完成耗时 |
| 显存需求 | 实测范围、输入形态、设备、额外峰值显存 |

耗时默认以中位数和样本数表示。边界字节源于结构推导，实际搬运字节来自测量。未归因的时间或状态保持未知。算法需要的图结构随结果提供。原始 trace、完整算子参数转储和数值对照按需保留。

首版 heuristic 可以从一个可评分的连续片段出发，尝试移动两侧边界。每步只更新新增或移除节点的执行成本和受影响的切边，并限制一次决策的尝试次数。传输时间按方向、字节和复制路径查表或插值。串行方案比较执行、搬运和额外准备耗时，已包含搬运的实测只计一次。峰值显存按同一执行窗口的活跃对象估计，再与可用显存及可比实测核对。

在线更新近期执行和搬运反馈及当前可用显存。反馈带上到达时间，供 heuristic 判断样本是否还适用。运行时比较当前可行方案与候选方案。若改变决策的关键成本缺测，或预计收益小于测量波动和切换开销所要求的余量，保留当前可行方案，并记录缺测原因或待补测范围。

## 控制采集开销与首版验收

- 两设备分别复用模型会话和已驻留权重。各轮用相同输入、种子及初始状态，交错运行不启用细粒度观察的基线。每轮单独报告相对基线的差值和波动。
- 相同结构只导出一次。计时轮沿用正常完成点，记录存入内存并批量取回，降低写盘和逐图 RPC 确认的开销。原路径上无法归因到单个算子的样本保留在可归因的粗粒度上。

Profiler 已输出整图耗时，以及理解图的层、块和可选算子耗时。短文本和图文理解实测有 27 组跨设备对齐的分层计时记录。状态读写、传输校准和峰值仍需在相应场景补齐。

首版离线排序先用现有理解数据评估不读写 KV 的 FFN 切分。记下理想搬运量，候选通过切点和显存检查后再做真实混合执行。Attention 侧后续校准不同历史长度下的 KV 搬运，生图侧后续关联单步、循环总耗时及实际状态交接。用留出的输入或切分方案做验证，对照纯 310P 和至少一组可执行的混合放置，核对预测的快慢顺序、实测端到端耗时和输出。实测差值落在重复测量的波动范围内时，记录为难以区分。
